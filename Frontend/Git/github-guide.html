1️⃣ GitHub Account kaise banaye

  1. Browser me github.com kholo
  2. Upar right me Sign up pe click karo
  3. Email daalo (jo regularly use karte ho)
  4. Password banao (strong rakho, 15+ characters ya 8+ with number aur letter)
  5. Username choose karo (professional rakho, jaise mdsakir-dev)
  6. Verification puzzle solve karo
  7. Email pe 6-digit code aayega, wahan daalo
  8. Account ready! ✅
💡 Tip: Settings → Password and authentication me jaake 2FA (Two-Factor Authentication) on kar lo. Fintech developer ho, security zaroori hai.

2️⃣ Git Install karna (Computer pe)

GitHub website alag hai, Git tool alag hai. Pehle Git install karna padega.

Windows

  1. git-scm.com pe jao
  2. Download karo aur install karo (sab default options rakho)

Mac

brew install git

Linux (Ubuntu)

sudo apt update
sudo apt install git

Check karo install hua ya nahi

git --version

3️⃣ Git ko apni Identity batao (One-time setup)

Terminal kholo aur yeh 2 commands chalao:

git config --global user.name "Md Sakir"
git config --global user.email "tumhara-github-email@example.com"
⚠️ Email wahi daalo jo GitHub account me hai, warna commits tumhare profile pe nahi dikhenge.

Check karne ke liye:

git config --list

4️⃣ Git ko GitHub se Connect karna (SSH Key, recommended)

Isse har baar password nahi dena padega.

Step 1: SSH key generate karo

ssh-keygen -t ed25519 -C "tumhara-github-email@example.com"
  • Enter dabate jao (default location accept karo)
  • Passphrase optional hai

Step 2: SSH agent start karo

eval "$(ssh-agent -s)"
ssh-add ~/.ssh/id_ed25519

Step 3: Public key copy karo

Mac:

pbcopy < ~/.ssh/id_ed25519.pub

Linux: output ko manually select karke copy karo

cat ~/.ssh/id_ed25519.pub

Windows (Git Bash):

clip < ~/.ssh/id_ed25519.pub

Step 4: GitHub me key add karo

  1. GitHub pe login karo
  2. Profile photo (top right) → Settings
  3. Left side me SSH and GPG keys
  4. New SSH key button dabao
  5. Title: kuch bhi (jaise "My Laptop")
  6. Key: jo copy kiya wo paste karo
  7. Add SSH key pe click karo

Step 5: Connection test karo

ssh -T git@github.com

Agar yeh message aaye to sab sahi hai:

Hi username! You've successfully authenticated...

5️⃣ GitHub pe Repository (Repo) kaise banate hai

  1. GitHub pe login karo
  2. Top right me + icon → New repository
  3. Yeh fill karo:
    • Repository name: jaise my-first-project
    • Description: (optional) project ke baare me
    • Public / Private: code secret hai to Private rakho
    • Add a README file: ✅ tick kar do

    • License: MIT (optional)
  4. Create repository pe click karo 🎉

6️⃣ Repo ko Clone kaise karte hai

Clone matlab GitHub ka repo apne computer pe download karna.

  1. Repo page pe jao
  2. Green Code button pe click karo
  3. SSH tab select karo
  4. Link copy karo, jaise git@github.com:mdsakir/my-first-project.git
  5. Terminal me jahan folder chahiye wahan yeh chalao:
git clone git@github.com:mdsakir/my-first-project.git

Folder ke andar jao:

cd my-first-project

Repo ko naya folder banaye bina current folder me clone karna

Agar tum pehle se ek empty folder ke andar ho aur repo ka naam wala extra folder nahi banana chahte, command ke end me . lagao:

git clone git@github.com:mdsakir/my-first-project.git .

Yahan . ka matlab current folder hai. Pehle us folder me jao, phir clone command chalao.

mkdir my-project
cd my-project
git clone git@github.com:mdsakir/my-first-project.git .
⚠️ Current folder empty hona chahiye. Agar usme pehle se files ya folders hain, Git clone fail ho sakta hai.

7️⃣ Local Project ko GitHub se Connect karna

Maan lo tumhara FastAPI project pehle se laptop me hai:

# 1. Project folder me jao
cd my-fastapi-project

# 2. Git initialize karo
git init

# 3. Saari files add karo
git add .

# 4. Pehla commit karo
git commit -m "Initial commit"

# 5. Branch ka naam main rakho
git branch -M main

# 6. GitHub repo se connect karo
git remote add origin git@github.com:mdsakir/my-fastapi-project.git

# 7. Code push karo
git push -u origin main
⚠️ Pehle GitHub pe empty repo bana lo (README ke bina), phir yeh commands chalao.

1️⃣1️⃣ Basic Terminal Commands (Folder & File Navigation)

1. Apna current folder (location) kaise dekhein?

pwd

2. Naya folder (directory) kaise banayein?

mkdir folder_name

3. Ek folder se dusre folder ke andar kaise jayein?

cd folder_name

4. Ek step peeche (back folder me) kaise jayein?

cd ..

5. Nayi file kaise banayein?

touch filename.html

6. Folder ke andar ki sabhi files aur folders ki list kaise dekhein?

ls

7. Hidden files (jaise .git) kaise dekhein?

ls -a

8. Terminal me kisi file ka content kaise padhein?

cat filename.html
💡 Windows PowerShell me touch kaam nahi karta. Git Bash use karo ya New-Item filename.html chalao.

1️⃣2️⃣ Git Repository Setup aur Basic Workflow

1. Project folder me Git ko initialize (start) kaise karein?

git init

2. Files ka current status (tracked/untracked) kaise check karein?

git status

3. Kisi ek specific file ko staging area me kaise add karein?

git add filename.html

4. Sabhi files ko ek sath staging area me kaise add karein?

git add .

5. Galti se add hui file ko staging area se wapas kaise hatayein?

git rm --cached filename.html
💡 Agar repo me pehla commit abhi tak nahi hua, tab yeh command sahi hai. Commit hone ke baad staging se hatane ke liye git restore --staged filename.html use karo, kyunki git rm --cached file ko Git ke tracking se hata deta hai.

6. Staged files ko permanently save (commit) kaise karein?

git commit -m "Yahan apna meaningful commit message likhein"

1️⃣5️⃣ Git Push, Pull aur Fetch

Yeh commands tumhare local repository aur GitHub (remote repository) ke beech changes sync karne ke kaam aati hain.

Push: local commits GitHub par bhejna

Apne current branch ke committed changes remote repository par upload karo:

git push origin main

Pehli baar kisi branch ko push karte waqt upstream set karne ke liye:

git push -u origin main
💡 main ki jagah apni current branch ka naam use karo. Push se pehle changes commit hone chahiye.

Fetch: remote updates check karna, bina apne files badle

GitHub se latest commits aur branch information lao. Isse tumhare working files ya current branch apne-aap change nahi hote:

git fetch origin

Apni local branch aur remote branch ke commits compare karne ke liye:

git log --oneline HEAD..origin/main

Updates ko dekhne ke baad apni current branch me merge karne ke liye:

git merge origin/main

Pull: remote updates lana aur current branch me integrate karna

git pull remote se updates fetch karke tumhari current branch me integrate karta hai. Kaam shuru karne se pehle latest main lana ho to:

git pull origin main
⚠️ Agar local changes hain, pehle unhe commit ya stash karo. Pull ke dauran merge conflict aaye to files me conflict resolve karke changes commit karo.

Short summary

  • Push: local commits → GitHub
  • Fetch: GitHub ke updates check/download karo; working files unchanged rehte hain
  • Pull: GitHub ke updates lao aur current branch me integrate karo

1️⃣6️⃣ Changes, Branches aur Remote check karna

Files me kya change hua hai?

# Working files ke unstaged changes dekho
git diff

# Staged changes dekho, jo next commit me jayenge
git diff --staged

# Current branch aur working tree ka status dekho
git status
💡 git diff tracked files ke changes dikhata hai. Nayi untracked files dekhne ke liye git status check karo.

Branches list aur switch karna

# Local branches list karo (* current branch hai)
git branch

# Existing branch par switch karo
git switch main

# Nayi branch banao aur us par switch karo
git switch -c feature/header

Purani git checkout command bhi chalti hai, lekin branch switch/create karne ke liye git switch zyada clear hai.

Remote repository check karna

Remote ka naam aam taur par origin hota hai. Yeh commands remote URL dekhne aur update karne ke kaam aati hain:

# Configured remote URLs dekho
git remote -v

# Remote ka URL badlo
git remote set-url origin git@github.com:username/repository.git
💡 origin remote ka naam hai; URL me apne GitHub username aur repository ka naam daalo.

1️⃣7️⃣ Branch Merge aur Conflict solve karna

Feature branch ka kaam complete hone par use main me merge kiya ja sakta hai. Pehle feature branch ke commits save aur push karo, phir:

# Main branch par jao aur latest changes lao
git switch main
git pull origin main

# Feature branch ko main me merge karo
git merge feature/header

# Updated main GitHub par bhejo
git push origin main

Merge conflict aaye to kya karein?

  1. git status chala kar conflicted files dekho.
  2. Har file kholo. Conflict markers <<<<<<<, =======, aur >>>>>>> ke beech apna final content decide karo.
  3. Markers hata kar file save karo.
  4. Resolved files stage karke merge commit complete karo.
git add filename
git commit
⚠️ Conflict resolve karte waqt dusre person ke changes ko bina samjhe delete mat karo. Merge cancel karna ho to, resolution shuru karne se pehle git merge --abort chalao.

1️⃣8️⃣ Stash: adhura kaam temporarily save karna

Branch switch karni ho lekin current changes commit ke liye ready na hon, to unhe stash me temporarily rakh sakte ho:

# Changes ko message ke saath stash karo
git stash push -m "header par kaam"

# Branch switch karke dusra kaam karo
git switch main

# Wapas apni branch par jao
git switch feature/header

# Sabse recent stash wapas lao aur stash entry hatao
git stash pop

Stash entries dekhne ke liye git stash list use karo. Entry ko list me rakhte hue apply karna ho to git stash apply use karo.

💡 Stash aam taur par tracked files ke changes save karta hai. Nayi untracked files bhi shamil karni hon to git stash push -u -m "message" chalao.

1️⃣9️⃣ Changes Undo karna (safe commands)

Undo command chalane se pehle git status dekho. Kuch undo commands local changes permanently hata sakti hain.

Working file ke uncommitted changes discard karna

git restore filename
⚠️ Isse us file ke uncommitted edits delete ho jate hain. Pehle backup ya commit kar lo agar changes chahiye ho sakte hain.

Staging se file hatana, lekin edits rakhna

git restore --staged filename

Existing commit ko safely undo karna

git revert ek naya commit banata hai jo purane commit ke changes ko reverse karta hai. Shared ya already-pushed branch par aam taur par yahi safer choice hai:

git log --oneline
git revert commit_id

Last commit ko edit karna

Sirf tab use karo jab commit abhi remote par push nahi hua ho:

git add filename
git commit --amend
⚠️ Pushed commit ko amend karne se shared history badalti hai. Team se coordinate kiye bina pushed commit amend ya force-push mat karo.

2️⃣0️⃣ Fork se Pull Request tak (Open-source workflow)

Fork kisi aur ke GitHub repository ki tumhare account me alag copy hoti hai. Original repository par direct write access na ho, tab fork workflow use karo.

  1. GitHub par original repo kholo aur Fork button dabao.
  2. Apne fork ka clone karo aur folder me jao.
  3. Original repo ko upstream remote ke naam se add karo.
  4. Alag branch me focused change karo, commit karo aur apne fork (origin) par push karo.
  5. GitHub par apne fork se original repo ke liye Pull Request banao.
# Apne fork ko clone karo
git clone git@github.com:your-username/project.git
cd project

# Original repository ko upstream remote banao
git remote add upstream git@github.com:original-owner/project.git

# Change ke liye branch banao
git switch -c fix/readme-typo

# Change commit karke apne fork par bhejo
git add .
git commit -m "Fix README typo"
git push -u origin fix/readme-typo

Pull Request me change ka reason likho, relevant issue link karo, aur reviewers ke feedback par isi branch me follow-up commits push karo.

💡 origin tumhara fork hai aur upstream original project. Local main update karne ke liye git fetch upstream karke reviewed changes merge karo.

2️⃣1️⃣ GitHub Issues aur Team Collaboration

Issues bugs, feature requests, questions aur task discussion track karte hain.

  1. Repository ke Issues tab me jaakar New issue select karo.
  2. Clear title aur steps/expected result ke saath description likho.
  3. Relevant labels, assignee, aur project/milestone set karo (agar available hon).
  4. Kaam ke liye branch banao; issue number ko branch ya PR description me mention karo.

Pull Request description me Closes #12 likhne se merge par isi repository ka issue automatically close ho sakta hai. #12 ko apne issue number se replace karo.

Pull Request review ka simple checklist

  • Change ka purpose aur test karne ke steps diye gaye hain.
  • Reviewers ne code aur automated checks dekhe hain.
  • Requested changes resolve hue hain aur checks pass hain.
  • Merge strategy project/team ke rules ke mutabik select hui hai.
💡 GitHub par Settings → Branches me branch protection rules laga kar PR review ya passing checks ko merge se pehle required bana sakte ho.

2️⃣2️⃣ Tags aur GitHub Releases

Tag kisi specific commit ko version naam se mark karta hai. Release us version ke saath notes aur downloadable files publish karne ka GitHub feature hai.

# Annotated version tag banao
git tag -a v1.0.0 -m "First stable release"

# Tag ko GitHub par bhejo
git push origin v1.0.0

# Existing tags dekho
git tag

Uske baad GitHub repository ke Releases section me jao, Draft a new release select karo, tag choose karo aur release notes likho.

⚠️ Published version tag ko move ya delete karne se release history confuse ho sakti hai. Version number publish karne se pehle check karo.

2️⃣3️⃣ GitHub Pages par Static Website Publish karna

GitHub Pages HTML, CSS aur JavaScript wali static sites host kar sakta hai. Server-side backend (jaise FastAPI) is tarah host nahi hota.

  1. Website files repository me push karo. Entry file aam taur par index.html hoti hai.
  2. GitHub par repo ke Settings → Pages kholo.
  3. Build and deployment ke Source me Deploy from a branch chuno.
  4. Branch, aam taur par main, aur folder /(root) select karke Save karo.
  5. Deployment complete hone ke baad Pages settings me diya gaya URL kholo.
💡 Project site ke URLs me repository ka naam path ka hissa ho sakta hai. Relative asset links use karo aur Settings → Pages me deployment status check karo.

❗ Common Errors

1. Permission denied (publickey)

SSH key GitHub me add nahi hui. Step 4 dobara karo.

2. fatal: not a git repository

Galat folder me ho. cd karke project folder me jao ya git init chalao.

3. rejected - non-fast-forward

Remote branch me aise commits hain jo tumhare local branch me nahi hain. Pehle git status check karo, phir remote changes fetch/pull karke zaroorat ho to conflict resolve karo; uske baad push karo.

4. Merge conflict

git status se conflicted files dekho, markers resolve karo, files ko git add karo aur merge complete karne ke liye commit karo. Steps ke liye Merge aur Conflict section dekho.

5. The current branch has no upstream branch

Pehli baar branch push karte waqt git push -u origin branch-name chalao. Isse remote tracking set hoti hai; aage git push aur git pull chala sakte ho.

6. remote origin already exists

Remote list check karo: git remote -v. URL badalna ho to git remote set-url origin repository-url use karo; same remote ko dobara add mat karo.

7. Changes galti se kho gaye

Agar commit hua tha to git log --oneline aur git reflog se recent history inspect karo. Recovery guaranteed nahi hoti; aage se important kaam commit ya stash karte raho.
