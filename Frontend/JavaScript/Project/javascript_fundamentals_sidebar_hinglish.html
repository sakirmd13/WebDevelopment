1. JavaScript kya hai?

JavaScript (JS) ek programming language hai jiska use web pages ko interactive aur dynamic banane ke liye kiya jata hai. HTML page ka structure banata hai, CSS design deta hai aur JavaScript behavior aur interaction add karta hai.

History & .js

JavaScript ko Brendan Eich ne 1995 mein Netscape ke liye banaya. Shuru mein iska naam Mocha tha, baad mein LiveScript aur phir JavaScript hua. JavaScript aur Java alag languages hain. JavaScript ko standardize karne ke liye ECMAScript standard use hota hai.

.js JavaScript files ka extension hai, jaise main.js.

Interview Questions (Medium–Hard)

  1. ECMAScript aur JavaScript mein kya relation hai?
    Answer

    ECMAScript language ka standard/specification hai. JavaScript us standard ko implement karne wali language hai; browser aur Node.js apne runtime APIs bhi dete hain.

  2. Kya JavaScript sirf browser mein chalti hai?
    Answer

    Nahi. Browser engines ke alawa Node.js jaise runtimes JavaScript ko server, terminal tools aur scripts mein chalate hain.

2. Low-level vs High-level language

Low-level

Hardware ke kareeb language, machine details zyada manage karne pad sakte hain.

10101010
MOV AX, 1

High-level

Human-readable aur abstractions ke saath comparatively aasaan language.

let total = 10 + 20;
console.log(total);

JavaScript high-level language hai.

Interview Questions (Medium–Hard)

  1. High-level language use karne ka fayda aur trade-off kya hai?
    Answer

    Abstraction se code readable aur portable hota hai; trade-off mein runtime, memory aur hardware-level control par kam direct control ho sakta hai. Engine optimization performance gap ko kam kar sakti hai.

  2. Kya high-level language hamesha low-level language se slow hoti hai?
    Answer

    Nahi. Performance workload, runtime, algorithms aur optimizations par depend karti hai; modern engines hot code ko JIT compile kar sakte hain.

3. Compiler vs Interpreter

Compiler

Source program ko target code mein translate karta hai, aksar execution se pehle. Example: C/C++ toolchains.

Interpreter

Runtime par program ko execute/process karta hai. Implementation details language/runtime par depend karti hain.

Modern JS engines (jaise V8) parsing, bytecode aur JIT compilation jaise techniques combine karte hain; JS engine ko sirf interpreter kehna oversimplification hai.

Interview Questions (Medium–Hard)

  1. Modern JavaScript ko “sirf interpreted” kehna incomplete kyun hai?
    Answer

    Engine source ko parse karta, bytecode bana sakta aur frequently executed code ko JIT compile/optimize kar sakta hai. Exact pipeline engine par depend karti hai.

  2. JIT optimization ke bawajood JavaScript engine ko runtime checks kyun karne padte hain?
    Answer

    JavaScript dynamic types aur runtime values allow karti hai. Engine assumptions ko guard karta hai; assumption invalid ho to optimized code deoptimize ho sakta hai.

4. JavaScript kyu use karte hain?

  • Button click, form validation, dropdowns.
  • DOM ke through HTML/CSS update.
  • API data fetch karke display.
  • React jaise frameworks mein UI development.
  • Node.js ke through servers, scripts, tooling.
  • Testing, automation, games aur app ecosystems.

Interview Questions (Medium–Hard)

  1. Browser JavaScript aur Node.js JavaScript mein kya common hai aur kya alag?
    Answer

    Language semantics aur engine features largely common hote hain; host APIs alag hote hain. Browser DOM/window deta hai, jabki Node.js filesystem aur process jaise APIs deta hai.

  2. Kya React ya Node.js JavaScript ke replacements hain?
    Answer

    Nahi. React UI library hai aur Node.js runtime; dono JavaScript ke upar ecosystem/tooling provide karte hain.

Script body ke end mein kyu, head mein kyu nahi?

Traditional script page parsing ko rok sakta hai jab download/execute ho. Body end par rakhne se HTML elements parse ho chuke hote hain. Modern alternative head mein defer:

<head>
 <script src="./main.js" defer></script>

Interview Questions (Medium–Hard)

  1. Head mein normal script DOM elements ko access karte waqt failure kyun de sakti hai?
    Answer

    Normal script parse ke waqt turant execute hoti hai; agar target DOM abhi parse nahi hua, query ko element nahi milega. Body-end placement ya defer is order ko solve karta hai.

  2. defer aur body ke end par script rakhne mein kya similarity/difference hai?
    Answer

    Dono DOM parse hone ke baad execution ensure kar sakte hain. defer file ko parallel download karta hai aur multiple deferred scripts ka order preserve karta hai.

11. Variable kya hota hai?

Variable ek named binding hai jiske through program value ko refer kar sakta hai. Analogy: label wale box mein value rakhi hui samajh sakte hain.

Syntax

Variable animation

JavaScript mein variable names case-sensitive hote hain. Capital aur small letters ko alag identifiers maana jaata hai.

console.log(Name);

    Answer

  2. Binding aur value ke difference ko object example se samjhaiye.
    Answer

    const user = {name: "A"} mein user binding reassign nahi ho sakti, par referenced object ki name property mutate ho sakti hai.

12. var, let & const

Declaration

Binding ka naam define karna.

let city;

Initialization

Binding ko initial value dena.

let city = "Delhi";

Updation

Baad mein nayi value assign karna.

city = "Patna";

var

Function-scoped, block scoped nahi. Redeclare aur reassign ho sakta hai; declaration scope mein hoist hokar undefined se initialize hota hai.

var score = 10;
var score = 15; // allowed redeclaration
score = 20; // reassignment
if (true) {
 var test = "visible outside block";
}
console.log(test);

Modern code mein var avoid karte hain, kyunki block scope na hone aur redeclaration se bugs ho sakte hain.

let

Block-scoped; reassign allowed, same scope mein redeclare nahi.

let age = 24;
age = 25; // valid
// let age = 26; // SyntaxError in same scope

Value change karni ho to let.

const

Block-scoped; declaration ke waqt initialize karna zaroori, binding reassign nahi. Objects/arrays ki contents mutate ho sakti hain.

const country = "India";
// country = "Nepal"; // TypeError
const skills = ["HTML", "CSS"];
skills.push("JavaScript"); // valid

Default const; reassignment chahiye to let. var ko legacy code samajhne ke liye padhein.

Common errors

  • ReferenceError: undeclared variable, ya let/const TDZ mein use.
  • SyntaxError: same scope let/const redeclaration, const without initializer, invalid syntax.
  • TypeError: const binding reassign karna.

Practice (2)

  1. Block mein var outer = "block var", let local aur const fixed declare karein; baad mein var print, let/const access errors ke naam print karein.
  2. TDZ access aur const reassignment ko alag try/catch mein run karke ReferenceError aur TypeError print karein.

Interview Questions (Medium–Hard)

  1. var, let aur const ki scope/hoisting mein kya differences hain?
    Answer

    var function-scoped hota hai aur declaration par undefined se initialize hota hai. let/const block-scoped hote hain, TDZ mein rehte hain, aur declaration se pehle access par error dete hain.

  2. const object mutate ho sakta hai, par variable reassign kyun nahi?
    Answer

    const binding ko nayi value/reference se reassign karne se rokta hai; referenced object ki internal properties ko freeze nahi karta.

13. Naming Rules

  • Letters, underscore _ ya dollar $ se start.
  • Digit se start nahi kar sakte.
  • Start ke baad digits allowed.
  • Spaces/hyphens identifiers mein allowed nahi.
  • Case-sensitive: age aur Age alag.
  • Reserved keywords jaise let, if, return, class identifier ke naam nahi.
// Valid
let userName = "Sakir";
let _count = 2;
let $price = 100;
let score2 = 5;

// Invalid (commented)
// let 2score = 5;
// let user-name = "Sakir";
// let let = 10;

Reserved Keywords

Language ke reserved words special syntax/roles ke liye reserved hain. Examples: if, else, let, const, var, return, class, while, for, function, new, this.

Practice (2)

  2. Invalid identifiers ko correct karein: 2name, user-name, class.

Interview Questions (Medium–Hard)

  1. Identifier case-sensitive hone ka practical effect kya hai?
    Answer

    score aur Score alag bindings hain; inconsistent capitalization se bugs aur confusing code ho sakta hai.

  2. Identifier valid hone ke bawajood uska naam poor choice kab hota hai?
    Answer

    Jab naam vague, misleading, reserved-term jaisa confusing, ya project convention ke against ho. Naam purpose bataye aur consistency follow kare.

14. Naming Conventions

Conventions style guidelines hain, strict syntax rules nahi.

camelCase

Words ke beech space nahi, next word ka first letter uppercase. Variables/functions mein common.

let firstName = "Sakir";

snake_case

Words underscore se separate. JS mein uncommon, lekin kuch projects/data context mein use.

let first_name = "Sakir";

PascalCase

Har word capital se start. Classes aur React component names mein common.

class StudentProfile {}

SCREAMING_SNAKE_CASE

Uppercase words underscore se separate; constants ke naming convention mein use.

const MAX_LIMIT = 100;

Practice (2)

  1. Ek product ka naam camelCase, snake_case, PascalCase aur SCREAMING_SNAKE_CASE mein likhein.
  2. Teen function names aur teen constant names ko project mein consistent style mein rename karein.

Interview Questions (Medium–Hard)

  1. Kya SCREAMING_SNAKE_CASE JavaScript mein constant ko immutable bana deta hai?
    Answer

    Nahi. Ye sirf naming convention hai. Immutability ke liye const binding use hoti hai; object contents phir bhi mutate ho sakte hain.

  2. Class aur function names ke liye PascalCase/camelCase use karne ka faayda kya hai?
    Answer

    Consistent conventions se codebase scan/read karna aasaan hota hai aur developers class constructors ko functions/variables se jaldi distinguish karte hain.

16. Type Conversion

Ek type ki value ko doosre type mein convert karna. Explicit conversion programmer karta hai; implicit conversion JS operations ke dauran.

// Explicit
console.log(Number("25")); // 25
console.log(String(25)); // "25"
console.log(Boolean(1)); // true
console.log(Boolean(0)); // false

// Implicit
console.log("5" + 2); // "52"
console.log("5" - 2); // 3
Number("hello") NaN deta hai; Boolean("false") true deta hai, kyunki non-empty strings truthy hoti hain.

Practice (2)

  1. Number("25"), String(25), Boolean(1), aur Boolean(0) ko alag-alag print karein.
  2. "5" + 2, "5" - 2, Boolean("") aur Number(null) ke results predict karke verify karein.

Interview Questions (Medium–Hard)

  1. "5" + 2 aur "5" - 2 ke results alag kyun hote hain?
    Answer

    + string operand milne par concatenation kar sakta hai, isliye "52". - numeric operator hai aur operands ko number mein coerce karke 3 deta hai.

  2. Number(""), Number(null) aur Number(undefined) kya return karte hain?
    Answer

    Number("") aur Number(null) 0 dete hain; Number(undefined) NaN deta hai.

Interview Questions (Medium–Hard)

  1. Template literal mein ${...} ke andar kya likh sakte hain?
    Answer

  2. Template literal aur string concatenation mein readability ka kya difference hai?
    Answer

    Template literal interpolation aur multiline text ko clear banata hai; concatenation simple cases mein theek hai, par multiple values/lines ke saath unreadable ho sakta hai.

18. Arithmetic Operators

Arithmetic operators numbers par calculations karte hain. + addition, - subtraction, * multiplication, / division, % remainder (modulus), aur ** exponentiation ke liye use hote hain. 

const a = 10;
const b = 3;

console.log("Addition:", a + b);       // 13
console.log("Subtraction:", a - b);    // 7
console.log("Multiplication:", a * b); // 30
console.log("Division:", a / b);       // 3.333...
console.log("Remainder:", a % b);      // 1
console.log("Exponent:", a ** b);      // 1000
% remainder deta hai, jaise 10 % 3 ka result 1. Kisi number ke even/odd hone ko check karne mein bhi useful hai.
const number = 8;
console.log(number % 2); // 0, even number

  2. 8 even hai ya nahi check karein; 17 ko 5 se divide karke integer quotient aur remainder labeled form mein print karein.

Interview Questions (Medium–Hard)

  1. JavaScript mein 10 / 0 aur 0 / 0 kya dete hain?
    Answer

    10 / 0 Infinity deta hai; 0 / 0 NaN deta hai. JavaScript number division by zero par aam taur par exception nahi throw karta.

  2. 0.1 + 0.2 === 0.3 false kyun hota hai?
    Answer

    Binary floating-point mein 0.1 aur 0.2 exact represent nahi hote, isliye sum mein tiny precision error hota hai. Decimal comparisons mein tolerance-based comparison use karein.

19. Operators

Comparison operators

Comparison operators values compare karke boolean (true/false) dete hain. Aam taur par === aur !== use karein: ye value ke saath type bhi compare karte hain. == type conversion kar sakta hai, isliye beginners ko ise avoid karna chahiye.

console.log(5 > 3);        // true
console.log(5 <= 5);       // true
console.log(5 === "5");    // false: type bhi different hai
console.log(5 == "5");     // true: type conversion hota hai
console.log(5 !== 4);      // true

Logical operators

Logical operators conditions ko combine ya reverse karte hain. Neeche true ka matlab condition sahi hai aur false ka matlab condition galat hai.

AND (&&) — dono conditions true honi chahiye

AND ka result sirf tab true hota hai jab A aur B dono true hon. Jaise movie entry ke liye age 18+ aur valid ID dono zaroori hon.

AND truth table
ABA && B
truetruetrue
truefalsefalse
falsetruefalse
falsefalsefalse

Example: Ticket aur 18+ age dono hon tabhi movie entry milegi.

const hasTicket = true;
const age = 20;
console.log(hasTicket && age >= 18); // true: dono conditions true hain
console.log(hasTicket && age < 18);  // false: age wali condition false hai

OR (||) — kam se kam ek condition true honi chahiye

OR ka result true hota hai agar A ya B mein se koi ek, ya dono, true hon. Jaise discount ke liye student hona ya senior citizen hona kaafi hai.

OR truth table
ABA || B
truetruetrue
truefalsetrue
falsetruetrue
falsefalsefalse

Example: Student ya senior citizen hone par discount milega.

const isStudent = false;
const isSeniorCitizen = true;
console.log(isStudent || isSeniorCitizen); // true: kam se kam ek true hai
console.log(false || false);               // false: dono conditions false hain

NOT (!) — condition ko ulta karta hai

NOT ek hi condition leta hai: true ko false aur false ko true bana deta hai. Jaise !isShopClosed ka matlab hai "shop band nahi hai".

NOT truth table
A!A
truefalse

Example: Shop band nahi hai to shopping kar sakte hain.

const isShopClosed = false;
console.log(!isShopClosed); // true: shop band nahi hai
console.log(!true);         // false: true ulta hokar false hua

Assignment & compound assignment operators

= variable ko value assign karta hai. Compound assignment mein pehle current value ke saath operation hota hai, phir result usi variable mein assign hota hai:

  • x += y: x = x + y (addition)
  • x -= y: x = x - y (subtraction)
  • x *= y: x = x * y (multiplication)
  • x /= y: x = x / y (division)
  • x %= y: x = x % y (remainder)
  • x **= y: x = x ** y (exponentiation)
let score = 10;
score = 12; // = assigns a new value
console.log("=:", score); // 12

score += 3;
console.log("+=:", score); // 15
score -= 5;
console.log("-=:", score); // 10
score *= 2;
console.log("*=:", score); // 20
score /= 4;
console.log("/=:", score); // 5
score %= 3;
console.log("%=:", score); // 2
score **= 3;
console.log("**=:", score); // 8

Unary plus, minus & logical NOT

Unary operator ek operand par kaam karta hai. +value number conversion karta hai; -value number ka sign reverse karta hai; !value value ko boolean mein convert karke truthiness reverse karta hai.

const textNumber = "8";
console.log(+textNumber); // 8
console.log(-textNumber); // -8
console.log(!true);       // false
console.log(!0);          // true

++ increment aur -- decrement operators bhi unary hain; ye number ko ek se badhate ya ghatate hain.

Pre-increment, post-increment, pre-decrement & post-decrement

  • ++x (prefix increment): pehle x ek se badhta hai, phir nayi value milti hai.
  • x++ (postfix increment): pehle purani value milti hai, phir x ek se badhta hai.
  • --x (prefix decrement): pehle x ek se ghatta hai, phir nayi value milti hai.
  • x-- (postfix decrement): pehle purani value milti hai, phir x ek se ghatta hai.
let postInc = 5;
console.log(postInc++); // 5: pehle old value use
console.log(postInc);   // 6: phir increment

let preInc = 5;
console.log(++preInc);  // 6: pehle increment
console.log(preInc);    // 6

let postDec = 5;
console.log(postDec--); // 5: pehle old value use
console.log(postDec);   // 4: phir decrement

let preDec = 5;
console.log(--preDec);  // 4: pehle decrement
console.log(preDec);    // 4
Complex expressions mein i++/++i se side effects samajhna mushkil ho sakta hai. Pehle increment/decrement alag statement mein karna zyada readable hai.
let score = 10;
score += 5; // score = score + 5
score -= 2;
score *= 2;
score /= 2;
console.log(score); // 13

let count = 0;
count++;
count--;
console.log(count); // 0

%= aur **= bhi compound assignment operators hain.

let remainder = 10;
remainder %= 3;
console.log(remainder); // 1

let power = 2;
power **= 3;
console.log(power); // 8

Nullish coalescing, optional chaining & spread

?? sirf null ya undefined par fallback deta hai; || falsy values jaise 0 aur empty string par bhi fallback deta hai. ?. missing/nullish property chain ko error ke bajaye undefined deta hai. Spread (...) iterable/object ko expand karta hai; object/array spread shallow copy banata hai.

console.log(0 || 10);  // 10
console.log(0 ?? 10);  // 0

const user = {};
console.log(user.address?.city); // undefined

const first = [1, 2];
const combined = [...first, 3];
console.log(combined); // [1, 2, 3]
const original = { name: "Asha" };
const copy = { ...original, age: 20 };
console.log(copy);

Interview Questions (Medium–Hard)

  1. == aur === mein kya farq hai, aur default mein kaunsa prefer karna chahiye?
    Answer

    == comparison se pehle type coercion kar sakta hai; === type aur value dono compare karta hai. Predictable behavior ke liye aam taur par strict equality prefer hoti hai.

  2. Logical AND/OR short-circuiting kaise karte hain, aur ?? kis case mein || se behtar hai?
    Answer

    AND left operand falsy ho to wahi return karta hai; OR truthy left operand par rukta hai. ?? sirf nullish values par fallback karta hai, isliye valid 0 ya empty string ko preserve karta hai.

  3. let n = 3; const old = n++; const current = ++n; ke baad old, current aur n ki values kya hongi?
    Answer

    old 3 hai; postfix n++ ke baad n 4 hota hai. Prefix ++n usse pehle 5 karta hai aur wahi value return karta hai, isliye current aur final n dono 5 hain.

  4. Loop mein array[i++] aur array[++i] ka access alag kyun ho sakta hai, aur complex expressions mein inka use risky kyun hai?
    Answer

    Postfix pehle current index use karta hai aur baad mein badhata hai; prefix pehle badhata hai aur naya index use karta hai. Side effects evaluation ko less readable bana sakte hain, isliye index update ko separate statement mein rakhna safer hai.

  5. x += y aur x = x + y ka result aam taur par same ho sakta hai; compound form ka practical benefit kya hai?
    Answer

    Compound form concise hota hai aur complex left-hand expression ko ek baar evaluate karta hai. Isliye side effects wale property/index expressions mein dono forms ka evaluation behavior alag ho sakta hai.

20. Conditions: if, else if & else

Condition ke basis par alag code chalane ke liye if, else if aur else use hote hain. Condition true ho to uska block chalta hai. Pehli matching condition ke baad baaki branches skip hoti hain.

Truthy & Falsy values

if condition mein JavaScript value ko boolean ke roop mein check karta hai. 0 falsy hai aur 1 truthy hai—yaani Boolean(0) false, Boolean(1) true. Number conversion mein Number(true) 1 aur Number(false) 0 deta hai; lekin true aur 1 alag types hain.

Common JavaScript falsy and truthy values
ValueBoolean(value)Category
false, 0, -0, 0nfalseFalsy
"", null, undefined, NaNfalseFalsy
true, 1, -1trueTruthy
"hello", [], {}trueTruthy

JavaScript mein in values ke alawa sab truthy hoti hain. Isliye empty string falsy hai, lekin empty array aur empty object truthy hain.

if (0) {
  console.log("Truthy");
} else {
  console.log("0 falsy hai"); // yahi print hoga
}

if ("hello") {
  console.log("Non-empty string truthy hai"); // yahi print hoga
}

console.log(Boolean(0), Boolean(1)); // false true
console.log(Number(false), Number(true)); // 0 1

if statement

if ke andar wali condition true ho tabhi uska code block chalta hai. Condition false ho to block skip ho jata hai.

const age = 20;

if (age >= 18) {
  console.log("Adult"); // condition true hai, isliye print hoga
}

else if statement

Pehla if false ho, tab else if ek aur condition check karta hai. Zarurat ke mutabik multiple else if branches laga sakte hain.

const marks = 76;

if (marks >= 90) {
  console.log("Grade A");
} else if (marks >= 60) {
  console.log("Pass"); // pehla false, yeh condition true
}

else statement

else ki apni condition nahi hoti. Isse tab chalaya jata hai jab usi chain ka if aur koi bhi else if true na ho. else optional hai aur chain ke end mein aata hai.

const age = 20;

if (age >= 21) {
  console.log("Allowed");
} else {
  console.log("Not allowed"); // condition false hai, isliye else chalega
}

Nested if...else

Jab ek if...else ke andar doosra if...else ho, use nested if...else kehte hain. Inner condition tabhi check hoti hai jab outer condition ka required path chale. Is example mein subscription check login ke baad hota hai.

const isLoggedIn = true;
const hasSubscription = false;
const wantsUpgrade = true;

if (isLoggedIn) {
  if (hasSubscription) {
    console.log("You can access premium content");
  } else {
    if (wantsUpgrade) {
      console.log("Please upgrade your subscription");
    } else {
      console.log("You don't have premium content");
    }
  }
} else {
  console.log("Please log in");
}

Code readability

Readable code ko samajhna aur maintain karna aasaan hota hai. Nested example ko same decision order ke saath else if chain mein likhne se indentation kam ho sakti hai:

const isLoggedIn = true;
const hasSubscription = false;
const wantsUpgrade = true;

if (!isLoggedIn) {
  console.log("Please log in");
} else if (hasSubscription) {
  console.log("You can access premium content");
} else if (wantsUpgrade) {
  console.log("Please upgrade your subscription");
} else {
  console.log("You don't have premium content");
}
  • Har block ke andar consistent indentation rakhein.
  • hasSubscription jaise meaningful variable names use karein.
  • Braces {} lagayein, chahe block mein ek hi statement ho.
  • Bahut zyada nesting se bachein; same decision ke liye else if chain use karein.

switch statement

Ek expression ki value ko kai exact cases ke saath compare karna ho to switch use kar sakte hain. Har case ke baad break aam taur par zaroori hai, warna agla case bhi chal sakta hai.

const day = "Saturday";

switch (day) {
  case "Saturday":
  case "Sunday":
    console.log("Weekend");
    break;
  case "Monday":
    console.log("Week start");
    break;
  case "Tuesday":
  case "Wednesday":
  case "Thursday":
  case "Friday":
    console.log("Weekday");
    break;
  default:
    console.log("Invalid day");
}

Ternary operator

Simple condition ke basis par value choose karne ka short form: condition ? valueIfTrue : valueIfFalse. Complex logic ke liye normal if/else zyada readable hai.

const age = 17;
const message = age >= 18 ? "Adult" : "Minor";
console.log(message);

Interview Questions (Medium–Hard)

  1. switch case matching mein type coercion hoti hai? Fall-through kab hota hai?
    Answer

    switch strict comparison ke equivalent matching karta hai. Matching case ke baad break na ho to execution agle case mein fall-through karta hai.

  2. [] aur {} conditions mein truthy kyun hain, aur common bug kya ho sakta hai?
    Answer

    JavaScript mein sab objects truthy hote hain, chahe empty hon. Empty array ko false samajhna bug hai; length ya explicit predicate check karein.

21. Loops

Loop ek block of code ko baar-baar chalata hai. Loop ki condition aur update dhyan se likhein, warna loop rukega nahi.

for loop

for loop tab useful hai jab repetitions/count ka idea ho. Ismein starting value, condition aur har round ka update ek hi line mein hota hai.

for (let i = 1; i <= 5; i++) {
  console.log("Count:", i);
}

while aur do...while loops

while condition true rehne tak chalta hai. do...while pehle code chalata hai, isliye condition false ho tab bhi ek baar zaroor run hota hai.

let count = 1;
while (count <= 3) {
  console.log("while:", count);
  count++;
}

let number = 1;
do {
  console.log("do...while:", number);
  number++;
} while (number <= 2);
Loop ke andar counter update karein, jaise count++, taaki condition aakhir mein false ho aur loop ruk jaaye.

for...of Loop

for...of kisi iterable ke har value par ek baar execute hota hai. Arrays aur strings jaise iterables ke values nikalne ke liye ise use karte hain.

const colors = ["red", "green", "blue"];
for (const color of colors) {
  console.log(color);
}

const word = "JS";
for (const character of word) {
 console.log(character);
}

for...in Loop

for...in object ki enumerable property keys par iterate karta hai. Object ki value access karne ke liye bracket notation object[key] use hota hai.

const user = { name: "Sakir", age: 24 };
for (const key in user) {
 console.log(key, user[key]);
}

// name Sakir
// age 24
Array ke values ke liye aam taur par for...of use karein; array ki property keys ke liye for...in kam predictable ho sakta hai.

break Statement

break loop ko turant poora band kar deta hai. Jaise hi desired value mil jaati hai, remaining iterations execute nahi hoti.

const numbers = [10, 20, 30, 40];
for (const number of numbers) {
 if (number === 30) break;
 console.log(number);
}

// 10
// 20

continue Statement

continue sirf current iteration skip karta hai aur next iteration par immediately jaata hai. Loop poora band nahi hota.

for (let i = 1; i <= 5; i++) {
 if (i === 3) continue;
 console.log(i);
}

// 1
// 2
// 4
// 5

  1. ["HTML", "CSS", "JavaScript"] ke har item ko for...of se print karein.
  2. { name: "Sakir", age: 24 } ki keys aur values ko for...in se print karein.
  3. [10, 20, 30, 40] mein 30 milne par break laga kar loop stop karein.
  4. 1 se 10 tak loop mein continue se even numbers skip karein aur sirf odd numbers print karein.

Interview Questions (Medium–Hard)

  1. for...in aur for...of mein kya difference hai, aur array values ke liye kaunsa use karenge?
    Answer

    for...in enumerable property keys deta hai; for...of iterable values deta hai. Array ke values iterate karne ke liye aam taur par for...of use karein.

  2. Infinite loop ke common causes kya hain aur ise debug kaise karenge?
    Answer

    Condition kabhi false na hona, counter update miss/galat hona, ya state update na karna common causes hain. Loop variables/condition inspect karein aur breakpoint ya temporary logging se iterations trace karein.

22. Functions

Function reusable code block hota hai. Use define karke zaroorat par call kar sakte hain; function input le sakta hai aur output return kar sakta hai.

Parameters, arguments & return

Definition mein diye names parameters, call karte waqt di hui values arguments hoti hain. return function se value bahar bhejta hai aur function execution end karta hai.

function add(a, b) {
  return a + b;
}

const total = add(4, 6); // 4 aur 6 arguments hain
console.log(total);      // 10

function greet(name = "friend") {
  return `Hello, ${name}!`;
}
console.log(greet());

Function expressions & arrow functions

Function ko variable mein store bhi kar sakte hain. Arrow function iska concise form hai; ek expression return karna ho to braces aur return omit kar sakte hain.

const multiply = function (a, b) {
  return a * b;
};

const square = number => number * number;
console.log(multiply(3, 4));
console.log(square(5));

Rest parameter (...) function ko multiple arguments ko ek array ke roop mein receive karne deta hai.

function sum(...numbers) {
 return numbers.reduce((total, number) => total + number, 0);
}
console.log(sum(1, 2, 3, 4));

Scope: global & local

Scope batata hai variable kahan accessible hai. Function ke andar declare kiya variable us function ka local variable hota hai; function ke bahar declare kiya variable outer scope mein hota hai.

const message = "Outer scope";
function showMessage() {
  const localMessage = "Function ke andar";
  console.log(message, localMessage);
}
showMessage();

  1. toFahrenheit(25) se Celsius ko Fahrenheit mein convert karke 77 return/print karein.
  2. Default array [1, 2, 3] lene wale arrow function se squares 1,4,9 aur count 3 print karein.

Interview Questions (Medium–Hard)

  1. Function declaration aur function expression ke hoisting behavior mein kya farq hai?
    Answer

    Function declaration apne scope mein call se pehle available hoti hai. Function expression variable ke initialization se pehle callable nahi; const/let TDZ bhi apply hoti hai.

  2. Arrow function aur normal function ke this behavior mein kya difference hai?
    Answer

    Normal function ka this call-site se bind hota hai; arrow function apna this nahi banata, lexical outer scope se leta hai.

23. Strings

String text data hai. Single quotes, double quotes, ya backticks use kar sakte hain. Strings immutable hoti hain: methods nayi string return karte hain, original ko change nahi karte.

console.log(text.length);                 // spaces bhi count hote hain
console.log(text.trim());                 // start/end spaces remove
console.log(text.toUpperCase());
console.log(text.includes("Script"));     // true
console.log(text.slice(2, 12));            // "JavaScript"

24. Arrays

Array ek ordered list hai. Index 0 se start hota hai; length item count deta hai. const array ko reassign nahi kar sakte, lekin uske items update kar sakte hain.

const fruits = ["apple", "banana", "orange"];
console.log(fruits[0]);       // apple
console.log(fruits.length);   // 3
fruits.push("mango");         // end mein add
fruits.pop();                 // end se remove
fruits[1] = "grape";          // item update
console.log(fruits);

Common methods: push/pop end se, unshift/shift start se item add/remove karte hain. includes item check karta hai; slice copy nikalta hai, jabki splice original array ko change karta hai.

const items = ["b", "c"];
items.unshift("a");                // start mein add
console.log(items.shift());        // "a", start se remove
console.log(items.slice(0, 1));    // copy: ["b"]
items.splice(1, 1, "new");         // original array ko change
console.log(items);
const numbers = [1, 2, 3, 4];
const doubled = numbers.map(number => number * 2);
const even = numbers.filter(number => number % 2 === 0);
const total = numbers.reduce((sum, number) => sum + number, 0);
numbers.forEach(number => console.log(number));
console.log(doubled, even, total);

map har item ko transform karke naya array deta hai; filter condition pass karne wale items ka naya array deta hai; forEach har item par action chalata hai; reduce items ko combine karke ek value banata hai. In methods ko function callback diya jata hai.

Practice (2)

  2. [1, 2, 2, 3] se unique values banayein aur unka total reduce se print karein.

Interview Questions (Medium–Hard)

  1. map, filter aur forEach ke outputs/uses kaise differ karte hain?
    Answer

    map transformed array deta hai, filter matching items ka array deta hai, aur forEach sirf har item par callback chalata hai; ise transformation chain ke result ke liye use nahi karte.

  2. slice aur splice ke mutation behavior mein kya farq hai?
    Answer

    slice original array ko nahi badalta aur shallow copy deta hai. splice original array ko add/remove/replace karke mutate karta hai.

26. Errors & debugging basics

Syntax error code parse hone se pehle, runtime error code chalne ke dauran aata hai. Console mein console.log(), console.error() aur browser ke DevTools breakpoints se values aur execution inspect kar sakte hain.

try...catch runtime error ko handle karta hai. finally optional hai aur success ya error dono cases mein chalta hai. throw se apni error raise kar sakte hain.

try {
  throw new Error("Something went wrong");
} catch (error) {
  console.log("Handled:", error.message);
} finally {
  console.log("Cleanup complete");
}

  2. Kya synchronous try...catch baad mein async callback mein aayi error ko pakad lega?
    Answer

    Nahi. Callback/promise baad mein execute ho sakta hai, jab try block khatam ho chuka ho. Async errors ke liye callback error handling ya promise ke catch/try...await pattern chahiye.
