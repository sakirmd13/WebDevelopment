1. Web aur HTML basics

HTML kya hai?

HTML ka full form HyperText Markup Language hai. Ye markup language web page ke content ko structure aur meaning deti hai—jaise heading, paragraph, link, image aur form. HTML programming language nahi hai: ismein general-purpose loops ya conditions nahi hote.

HTML

Page ka content aur structure: “ye heading hai”, “ye form hai”.

CSS

Presentation: colors, spacing, layout aur responsive design.

JavaScript

Behavior: button click, validation, calculations aur dynamic updates.

Browser page kaise dikhata hai?

  1. Browser URL se server ko request bhejta hai.
  2. Server HTML bhejta hai; browser usse parse karke DOM tree banata hai.
  3. CSS styles apply hote hain aur JavaScript zarurat par page ko interactive banata hai.
“HTML compiler” ke baare mein: HTML aam taur par compile nahi hota. Browser HTML ko parse karke render karta hai. Isliye is course ka playground editor/preview tool hai—ye code ko browser ke sandboxed preview mein dikhata hai.

Apna pehla HTML file

VS Code ya kisi text editor mein index.html naam ki file banayein. File extension .html honi chahiye. Browser mein file kholkar result dekhein; code badalne ke baad page refresh karein.

2. HTML document ka basic structure

Har normal HTML page mein document declaration, root html, metadata wala head aur visible content wala body hota hai.

<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Mera pehla page</title>
</head>
<body>
  <h1>Namaste, duniya!</h1>
  <p>Mera pehla HTML page.</p>
</body>
</html>
  • <!doctype html> browser ko modern HTML mode use karne ko kehta hai.
  • <html lang="en"> root element hai. Page Hinglish/Hindi mein ho to lang="hi" ya content ke mutabik sahi language set karein.
  • <head> mein title, metadata aur stylesheets jaise page-related information aati hai.
  • <body> mein page ka visible content hota hai.
  • charset="utf-8" Hindi aur doosre characters ko sahi dikhane mein madad karta hai.
  • Viewport meta mobile browser ko page ki width device ke mutabik set karne deta hai.

HTML comments

Comment browser page par render nahi karta. Iska use code notes ke liye karein; password ya private data comment mein kabhi na rakhein, kyunki source mein dikh sakta hai.

<!-- Ye comment page par nahi dikhega -->
<p>Ye visible paragraph hai.</p>

Head ke common tags

title tab/window ka page title; meta metadata; link external resource; style embedded CSS; base relative URLs ka base URL set karta hai. base ka effect poore document ke relative links par hota hai, isliye ise soch-samajhkar use karein.

<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>HTML Practice</title>
  <link rel="stylesheet" href="style.css">
  <style>
    body { font-family: sans-serif; }
  </style>
</head>

JavaScript file load karne ke liye script use hota hai. External classic script ke liye defer aksar achha default hai; module scripts ka execution behavior alag hota hai.

<script src="main.js" defer></script>
<script type="module" src="app.js"></script>
  • defer: HTML parse hone ke baad execute; deferred classic scripts document order follow karte hain.
  • async: download ke baad jaldi execute; multiple scripts ka order guaranteed nahi, isliye independent scripts ke liye use karein.
  • type="module": JavaScript module; deferred behavior default hota hai, aur module imports support hote hain.

3. Elements, tags, nesting aur attributes

Tag markup ka start/end syntax hai. Opening tag, content aur closing tag milkar aam taur par ek element banate hain.

<p class="intro">Ye paragraph element hai.</p>
  • <p> opening tag hai; </p> closing tag hai.
  • class="intro" attribute hai—extra information jo element ko identify/style karne mein madad karti hai.
  • Attribute value aam taur par quotes mein likhein.
  • Elements ko sahi order mein nest karein; pehle khula inner element pehle band hota hai.
<p>Ye <strong>important</strong> text hai.</p>
Galat nesting: <p><strong>Text</p></strong>. Ismein tags ka closing order ulta hai.

Void elements

Kuch elements ke andar child content nahi hota, isliye unka closing tag nahi hota. Inhe void elements kehte hain.

<img src="photo.jpg" alt="Pahadon ka nazara">
<br>
<hr>
<input type="text" name="username">
<meta charset="utf-8">

HTML mein <br /> likhna zaroori nahi; standard void tag <br> hai.

Block aur inline—practical samajh

Ye display behavior hota hai, semantic meaning nahi. Aam taur par div block container aur span inline wrapper hota hai; CSS se display behavior badal sakta hai.

<div>Ye ek generic block container hai.</div>
<p>Paragraph ke andar <span>chhota inline hissa</span> hai.</p>

Layout ke liye CSS Flexbox/Grid ko prefer karein; har cheez ko div banane ke bajay semantic element chunein jab suitable ho.

4. HTML elements ka quick reference

Yeh current HTML standard ke built-in elements ko category ke hisaab se group karta hai. Har tag ko har page mein use karna zaroori nahi—content ke meaning ke mutabik chunein. Kisi tag ka detail example us topic ke section mein milega.

Obsolete / avoid karne wale tags

acronym, applet, basefont, big, center, command, dir, font, frame, frameset, keygen, listing, menuitem, noframes, param, plaintext, strike, tt, xmp, marquee jaise purane/obsolete tags modern pages mein use na karein. Meaning ke liye modern semantic tags aur appearance ke liye CSS chunein.

5. Headings, paragraphs aur text formatting

Headings ka hierarchy

h1 se h6 tak headings document ki outline batati hain. Aam taur par page/topic ka main heading h1 hota hai; subsections ke liye logical order mein h2, phir h3 use karein. Sirf font size paane ke liye heading level na chunein—visual styling CSS se karein.

<h1>Travel Guide</h1>
  <h2>India</h2>
    <h3>Rajasthan</h3>
  <h2>Japan</h2>

Paragraph aur line breaks

p paragraph ke liye hai. br sirf meaningful line break (jaise address ya poem) ke liye use karein—spacing banane ke liye CSS margin behtar hai. hr topic change jaisa thematic break dikhata hai.

<p>HTML page ko structure deta hai.</p>
<p>CSS page ko style karta hai.</p>
<hr>
<p>Ab agla topic shuru hota hai.</p>

Meaningful text elements

Element Meaning / use
strong Important content; default browser bold dikhata hai.
em Emphasis; default browser italic dikhata hai.
mark Context mein relevant highlighted text.
small Side note ya fine print.
del / ins Removed / inserted text.
sub / sup Subscript / superscript.
code / pre Inline code / whitespace-preserving preformatted text.
blockquote / q Long / short quotation. 
<p>Is topic ka <strong>important point</strong> yaad rakhein.</p>
<p>Formula: H<sub>2</sub>O; power: x<sup>2</sup>.</p>
<p>Shortcut: <code>Ctrl + S</code></p>
<blockquote>Practice se concepts clear hote hain.</blockquote>

b aur i visual bold/italic hain; meaning batana ho to context ke mutabik strong aur em zyada upyogi hain.

Extra text semantics

abbr abbreviation, cite creative work ka title, dfn define kiya ja raha term, address contact information, kbd user input, samp program output, var variable, time machine-readable date/time aur data machine-readable value deta hai. bdi/bdo bidirectional text; ruby/rt/rp pronunciation annotations ke liye hain. wbr optional line-break opportunity batata hai.

<p><abbr title="HyperText Markup Language">HTML</abbr> seekhein.</p>
<p>Book: <cite>The Web</cite>; term: <dfn>markup</dfn>.</p>
<address>Contact: <a href="mailto:hello@example.com">hello@example.com</a></address>
<p>Save karne ke liye <kbd>Ctrl</kbd> + <kbd>S</kbd> dabayein.</p>
<p>Output: <samp>Saved</samp>; variable: <var>total</var>.</p>
<p>Updated: <time datetime="2026-11-27">27 Nov 2026</time></p>
<p><data value="sku-42">Blue T-shirt</data></p>
<p>User <bdi>علي</bdi> ne message bheja.</p>
<p>Fixed direction: <bdo dir="rtl">ye text right-to-left hai</bdo>.</p>
<p><ruby>漢<rp>(</rp><rt>kan</rt><rp>)</rp></ruby></p>
<p>Version <del datetime="2026-01-01">1.0</del> <ins datetime="2026-02-01">2.0</ins> hai.</p>
<p>Unhone kaha, <q>practice roz karein</q>.</p>
<p>Long-word<wbr>break-point</p>

s ab relevant na rehne wali information dikhata hai; u non-text annotation ke liye hai. Sirf look ke liye in tags ko na chunein.

6. Links aur images

Anchor link

a element kisi page, file, email ya page ke section se link karta hai. href destination hota hai.

<!-- External page -->
<a href="https://developer.mozilla.org/">HTML docs dekhein</a>

<!-- Isi page ke section tak -->
<a href="#forms">Forms topic par jaayein</a>

<!-- Email link -->
<a href="mailto:hello@example.com">Email bhejein</a>

<!-- New tab: external untrusted link ke liye rel bhi lagayein -->
<a href="https://example.com" target="_blank" rel="noopener noreferrer">Nayi tab</a>

Same website ke links par aksar same tab behtar hota hai. Link text destination ko clear bataye; “yahan click karein” jaise vague text se bachein.

Relative aur absolute paths

  • images/photo.jpg current folder se relative path.
  • ../images/photo.jpg ek parent folder upar.
  • /images/photo.jpg site root se path.
  • https://example.com/photo.jpg absolute URL.

Images aur alt text

img void element hai. src image ka path aur alt uska text alternative hai. Informative image ko meaningful alt dein; decorative image ka alt empty (alt="") rakhein, taaki assistive technology usse ignore kar sake.

<figure>
  <img src="images/mountain.jpg"
       alt="Subah ki roshni mein barf se dhaka pahad"
       width="800" height="500">
  <figcaption>Himalaya ka ek nazara.</figcaption>
</figure>

<!-- Decorative image -->
<img src="images/squiggle.png" alt="">

Apne project mein image file ka path aur spelling check karein. Width/height dene se browser layout space pehle reserve kar sakta hai.

Responsive images: picture, source aur srcset

Alag screen/density ke liye browser ko image choices deni ho to srcset/sizes ya art direction ke liye picture use karein.

<picture>
  <source media="(max-width: 600px)" srcset="images/portrait-small.jpg">
  <source type="image/webp" srcset="images/portrait.webp">
  <img src="images/portrait.jpg"
       srcset="images/portrait-2x.jpg 2x"
       alt="Profile portrait"
       width="600" height="400">
</picture>

Image map: map aur area

Ek image ke alag clickable regions define karne ke liye map aur area hote hain. Har clickable area ka meaningful alt dein; responsive image scaling ke saath coordinates maintain karna mushkil ho sakta hai.

<img src="floor-plan.png" usemap="#rooms" alt="Room select karne ka floor plan">
<map name="rooms">
  <area shape="rect" coords="0,0,120,100" href="#kitchen" alt="Kitchen">
  <area shape="circle" coords="200,80,40" href="#lounge" alt="Lounge">
</map>
<section id="kitchen"><h2>Kitchen</h2></section>
<section id="lounge"><h2>Lounge</h2></section>

7. Lists

Unordered list

Jahan order important na ho, ul ke andar har item ke liye li use karein. 

<ul>
  <li>HTML</li>
  <li>CSS</li>
  <li>JavaScript</li>
</ul>

Ordered list

Steps ya ranking jahan order matter karta hai, wahan ol use karein. start starting number set karta hai; numbering ka style CSS se control karna aam tor par behtar hai.

<ol>
  <li>File banayein</li>
  <li>HTML likhein</li>
  <li>Browser mein test karein</li>
</ol>

Description list

Term/label aur uski definition ya value ke pairs ke liye dl, dt aur dd ka use hota hai.

<dl>
  <dt>HTML</dt>
  <dd>Web content ko structure karne ki markup language.</dd>
  <dt>CSS</dt>
  <dd>Web page ko style karne ki language.</dd>
</dl>

Ek list item ke andar nested list ho sakti hai. Har item ko sahi parent list ke andar rakhein.

menu command/action items ki list ke liye element hai aur aksar ul jaisa render hota hai. Site navigation ke links ke liye nav ke andar normal list/anchors use karna clear pattern hai.

8. Tables

Table ko tabular data ke liye use karein—page layout banane ke liye nahi. Rows tr, header cells th aur data cells td se banti hain.

<table>
  <caption>Course schedule</caption>
  <thead>
    <tr>
      <th scope="col">Din</th>
      <th scope="col">Topic</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <th scope="row">Somvar</th>
      <td>HTML basics</td>
    </tr>
    <tr>
      <th scope="row">Mangalvar</th>
      <td>Forms</td>
    </tr>
  </tbody>
</table>
  • caption table ka title/description deta hai.
  • thead, tbody, optional tfoot rows ko group karte hain.
  • scope="col" ya scope="row" header ka sambandh batata hai.
  • colspan columns aur rowspan rows span karta hai. Zarurat na ho to cells ko merge na karein—simple tables samajhna aasaan hota hai.

colgroup aur col columns ko group karne/metadata dene ke liye hain, data cells ki jagah nahi lete.

<table>
  <caption>Quarterly results</caption>
  <colgroup>
    <col span="1">
    <col span="2">
  </colgroup>
  <thead><tr><th scope="col">Quarter</th><th scope="col">Sales</th><th scope="col">Cost</th></tr></thead>
  <tbody><tr><th scope="row">Q1</th><td>100</td><td>60</td></tr></tbody>
  <tfoot><tr><th scope="row">Total</th><td>100</td><td>60</td></tr></tfoot>
</table>

9. Forms aur input controls

Form user se information leta hai. Har control ka meaningful name hona chahiye, aur uske saath visible label jodna chahiye. id label ko control se connect karta hai.

<form action="/signup" method="post">
  <div>
    <label for="full-name">Aapka naam</label>
    <input id="full-name" name="fullName" type="text" required>
  </div>

  <div>
    <label for="email">Email</label>
    <input id="email" name="email" type="email" autocomplete="email" required>
  </div>

  <button type="submit">Account banayein</button>
</form>

Datalist, file aur button controls

<label for="fav-language">Favorite language</label>
<input id="fav-language" name="language" list="language-options">
<datalist id="language-options">
  <option value="HTML">
  <option value="CSS">
  <option value="JavaScript">
</datalist>

<label for="resume">Resume file</label>
<input id="resume" name="resume" type="file" accept=".pdf" multiple>

<button type="button">Do not submit</button>

<button type="submit">Submit form</button>

Button ke andar form mein type explicitly set karein: default submit behavior ho sakta hai. multiple file ya select controls ko multiple values allow karta hai.

Customizable select ka newer pattern

selectedcontent customizable select ke andar currently selected option ka content dikhane ke kaam aata hai. Ye newer feature hai; browser support verify karein aur basic select/option ko workable fallback rakhein.

<select name="course">
  <button><selectedcontent></selectedcontent></button>
  <option value="html">HTML Foundations</option>
  <option value="css">CSS Essentials</option>
</select>

GET aur POST ka basic difference

  • GET read/search jaisi request ke liye; data URL query mein dikh sakta hai aur bookmark/share kiya ja sakta hai.
  • POST form data request body mein bhejta hai. POST khud encryption ya security guarantee nahi karta—sensitive data ke liye HTTPS aur server-side security zaroori hai.
  • Browser validation helpful hai, lekin server ko bhi input validate karna hota hai. HTML validation ko security boundary na samjhein.

10. Semantic HTML aur page layout

Semantic elements apne content ka role/meaning batate hain—browser, developer aur assistive technology ko page samajhne mein madad milti hai. Sirf appearance badalne ke liye semantic element na chunein.

<body>
  <header>
    <a href="/">Site ka naam</a>
    <nav aria-label="Main navigation">
      <a href="/about">About</a>
      <a href="/contact">Contact</a>
    </nav>
  </header>

  <main>
    <article>
      <h1>HTML seekhne ki guide</h1>
      <section>
        <h2>Shuruaat</h2>
        <p>Article ka main content.</p>
      </section>
    </article>
    <aside>Related links</aside>
  </main>

  <footer>Copyright information</footer>
</body>
  • header: page ya section ka introductory content.
  • nav: important navigation links ka group.
  • main: page ka primary content; aam taur par ek visible main landmark.
  • article: independently meaningful content, jaise post ya news story.
  • section: related content ka thematic group; aksar heading ke saath.
  • aside: main content se related, par secondary content.
  • footer: page/section ka closing information.

hgroup heading aur uske saath subtitle/tagline ko group karta hai. search search-related controls/region ko mark karta hai. Ye tags default look ke liye nahi—meaning ke liye hain.

<search aria-label="Site search">
  <form action="/search" method="get">
    <label for="site-query">Search</label>
    <input id="site-query" name="q" type="search">
    <button type="submit">Find</button>
  </form>
</search>

<hgroup>
  <h1>Learn HTML</h1>
  <p>A practical beginner guide</p>
</hgroup>

div generic container hai—jab koi semantic element suitable na ho tab use karein.

11. Audio, video, figure aur iframe

Image ko caption dena

Jab image aur caption ka sambandh ho, figure aur figcaption sahi structure dete hain. Images ke liye alt text ka rule phir bhi apply hota hai.

Audio aur video

Browser controls dikhane ke liye controls attribute use karein. Captions/transcript provide karein; autoplay, khaaskar sound ke saath, avoid karein.

<audio controls preload="metadata">
  <source src="audio/lesson.mp3" type="audio/mpeg">
  Aapka browser audio playback support nahi karta.
</audio>

<video controls width="640" poster="images/preview.jpg">
  <source src="video/lesson.mp4" type="video/mp4">
  <track kind="captions" src="captions-en.vtt" srclang="en" label="English">
  Aapka browser video playback support nahi karta.
</video>

Iframe

iframe doosre page/document ko embed karta hai. Title zaroor dein. Unknown content ko embed karte waqt sandbox permissions samajhkar hi set karein; sirf zarurat ke permissions dein.

<iframe
  src="https://example.com/embed"
  title="Example page preview"
  loading="lazy"
  sandbox
  width="600"
  height="400">
</iframe>

embed aur object bhi external/embedded resources ke liye hain. Inka use zaroorat par karein, fallback content dein, aur unknown files/plugins ko blindly trust na karein. 

<object data="document.pdf" type="application/pdf" width="600" height="400">
  <p>PDF nahi khul raha? <a href="document.pdf">PDF download karein</a>.</p>
</object>
Embed providers ki terms aur privacy settings check karein. Cross-origin iframe ka content parent page se aam taur par freely read nahi kiya ja sakta.

12. Extra useful aur interactive elements

Details aur summary

Native expandable/collapsible disclosure ke liye details ke andar pehla summary uska visible label hota hai. Open state ko open attribute se default khola ja sakta hai.

<details>
  <summary>HTML ka full form kya hai?</summary>
  <p>HyperText Markup Language.</p>
</details>

Dialog

dialog dialog box hai. open attribute se non-modal dialog dikh sakta hai. Modal dialog kholne/band karne ke liye JavaScript ke showModal()/close() methods chahiye—focus aur keyboard behavior bhi test karein.

<dialog open aria-labelledby="notice-title">
  <h2 id="notice-title">Notice</h2>
  <p>Yeh open non-modal dialog ka example hai.</p>
</dialog>

Datalist, output, progress aur meter

datalist input suggestions deta hai, fixed selection list nahi. progress task completion aur meter known range ke andar measurement dikhata hai. output calculation ka result batata hai.

<label for="browser">Browser chunein ya type karein</label>
<input id="browser" name="browser" list="browsers">
<datalist id="browsers">
  <option value="Firefox">
  <option value="Chrome">
</datalist>

<label for="upload">Upload progress</label>

13. Common attributes aur HTML entities

Global attributes

Attribute Kaam Dhyan rakhein
id Ek element ko unique identifier deta hai. Ek page mein same id repeat na karein.
class Elements ko group/style/target karta hai. Ek element par multiple classes ho sakti hain.
title Additional advisory text. Important instruction ka eklauta source na banayein.
lang Content ki language batata hai. Language code content se match hona chahiye.
dir Text direction: ltr, rtl ya auto. Right-to-left language/content mein useful.
hidden Element ko currently hide karta hai. Secret/private data hide karne ka tareeqa nahi.
contenteditable Element ka content browser mein editable karta hai. Data save karne ke liye app logic chahiye.
tabindex Keyboard focus behavior control karta hai. Natural tab order ko badalne wala positive number avoid karein.
spellcheck, translate, draggable Spell checking, translation preference, drag behavior. Feature browser/user settings par depend kar sakta hai.
style Inline CSS declarations. Reusable styling ke liye external stylesheet prefer karein.
data-* Custom data attribute. Example: data-product-id.
aria-*, role Accessibility semantics/states. Native semantic HTML ko replace nahi karte; sahi use zaroori.

Common element-specific attributes

Links: href, target, rel, download. Images/media: src, alt, srcset, sizes, width, height, controls, poster, preload, loading. Forms: name, value, type, for, action, method, autocomplete, required, disabled, checked, selected, multiple, min, max, step, pattern. Tables: scope, colspan, rowspan. Script/resource loading: async, defer, type, integrity, crossorigin. Har attribute har tag par valid nahi hota—element documentation check karein.

<div id="notice" class="message" lang="en" dir="ltr"
     data-kind="tip" contenteditable="false">
  Attribute values ko element ke context mein samjhein.
</div>

Boolean attributes

required, disabled, checked jaise boolean attributes ki presence true hoti hai. required="false" bhi attribute present hone ki wajah se true hai; false karna ho to attribute hata dein.

<input type="email" required>
<button type="button" disabled>Abhi unavailable</button>
<input type="checkbox" checked>

Special characters / entities

Character Entity Meaning
& &amp; Ampersand
< &lt; Less-than sign

non-breaking space &nbsp; Line break na hone wali space (layout ke liye CSS prefer karein)

14. Accessibility basics

Accessible HTML ka matlab hai ki alag-alag abilities aur devices wale log content ko perceive, navigate aur use kar sakein.

  • Har page par content ki language set karein; heading levels logical rakhein.
  • Images ko context ke mutabik useful alt dein; decorative images ke liye empty alt.
  • Har form control ko visible label se connect karein. Placeholder label ka replacement nahi.
  • Links ka text bataye ki link kahan le jayega; buttons actions ke liye use karein.
  • Keyboard se tab karke controls use ho pa rahe hain, check karein. Native button/link ko preference dein.
  • Sirf color ke zariye information na dein; readable contrast rakhein.
  • Media ke liye captions/transcript aur iframe ke liye descriptive title dein.
<label for="search">Course search</label>
<input id="search" name="q" type="search">
<button type="submit">Search</button>

Accessibility ko sirf ARIA attributes add karke solve nahi kiya ja sakta. Pehle semantic native HTML use karein; ARIA tab add karein jab native element required meaning/behavior na de.

15. SEO, validation aur best practices

Head metadata

<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Beginner HTML Guide | Example Site</title>
  <meta name="description" content="HTML basics ko examples ke saath seekhein.">
</head>

Page title ko specific aur useful rakhein. Description search result mein use ho sakti hai, lekin search engines usse badal bhi sakte hain—ranking ka guaranteed shortcut nahi.

Clean HTML checklist

  • Indentation consistent rakhein aur tag nesting validate karein.
  • Har page mein unique title, correct language aur viewport metadata ho.
  • Semantic tags aur descriptive links use karein.
  • Deprecated/presentational tags jaise font, center avoid karein; styling CSS se karein.
  • JavaScript ya server par aane wale data ko validate/sanitize karein; HTML form validation akeli security nahi hai.
  • Images/media ka size, alt/captions aur loading behavior check karein.
  • HTML validator aur keyboard testing se page review karein.

Valid HTML bugs dhoondhne mein help karta hai, lekin validation pass hona accessibility, security, design ya content quality ki guarantee nahi.

19. HTML interview questions aur answers

1. HTML kya hai?

HTML web content ko structure aur meaning dene wali markup language hai. Ye general-purpose programming language nahi hai.

2. HTML ka full form kya hai?

HyperText Markup Language.

3. HTML aur HTML5 mein kya antar hai?

HTML5 HTML standard ka modern generation label tha. Aaj standard WHATWG Living Standard ke roop mein evolve hota hai; semantic, media aur form features modern HTML ka hissa hain.

4. <!doctype html> kyu likhte hain?

Browser ko standards mode mein document parse karne ka signal deta hai; ye normal HTML element nahi hai.

5. head aur body mein kya difference hai?

head mein title/metadata/resources; body mein page ka visible content hota hai.

6. Tag aur element mein kya difference hai?

Tag markup syntax, jaise <p>; element aam taur par opening tag, content aur closing tag ka complete unit hai.

7. Semantic HTML kya hota hai?

Aise elements jo content ka role batate hain, jaise nav, main, article. Ye structure ko readable aur assistive technology ke liye meaningful banate hain.

8. div aur span mein kya difference hai?

Dono generic containers hain. Default display behavior alag hota hai, lekin meaning nahi batate. Suitable semantic element ho to usse prefer karein.

9. Block aur inline elements kya hain?

Ye common default layout behaviors hain: block element aam taur par nayi line se shuru hota hai; inline text flow mein rehta hai. CSS display behavior badal sakta hai.

10. Void element kya hai?

Jis element ka child content/closing tag nahi hota, jaise img, br, hr, input.

11. alt attribute kyu important hai?

Image ka text alternative deta hai—screen reader aur image load na hone par madad karta hai. Decorative image ke liye empty alt="" ho sakta hai.

12. id aur class mein difference?

id ek page par unique identifier hona chahiye; class kai elements share kar sakte hain aur ek element par multiple classes ho sakti hain.

13. Relative aur absolute URL kya hote hain?

Relative URL current/site folder ke hisaab se resolve hota hai; absolute URL mein full scheme aur host hota hai.

14. HTML entities ka use kya hai?

Reserved characters ya special symbols ko text ke roop mein dikhane ke liye, jaise &lt; less-than sign ke liye.

15. Form mein label kaise associate karte hain?

Label ke for attribute ko control ke id ke barabar rakhein; ya control ko label ke andar nest karein.

16. GET aur POST mein difference kya hai?

GET data URL query mein bhej sakta hai aur retrieval/search ke liye suitable hai. POST request body mein data bhejta hai. POST encryption nahi hai; HTTPS zaroori hai.

17. required aur placeholder ka kya kaam hai?

required browser-side constraint validation mein field required banata hai. Placeholder hint hai, label nahi; field ka naam visible label se dena chahiye.

18. Table ko layout ke liye use karna chahiye?

Nahi, table tabular data ke liye hai. Page layout ke liye CSS Flexbox/Grid use karein.

19. strong aur b mein kya difference?

strong importance batata hai; b attention draw karta hai bina extra importance imply kiye. Default visual style CSS se badal sakta hai.

20. em aur i mein difference?

em emphasis deta hai; i alternate voice/mood ya technical term jaisa text mark karta hai. Context ke mutabik chunein.

21. Responsive page ke liye viewport meta kyu hota hai?

Mobile browser ko layout viewport device width se match karne mein madad karta hai, taaki responsive CSS expected tarah kaam kare.

22. defer script attribute ka kya kaam hai?

External script ko HTML parsing ke saath download karke document parse hone ke baad execute karta hai. Ye HTML concept ke saath JS loading ka useful integration point hai.

23. HTML validation kya guarantee karti hai?

Validator markup errors/warnings dhoondhne mein madad karta hai. Pass hona accessibility, security, visual quality ya correct business behavior ki guarantee nahi.

24. iframe ko accessible kaise banayein?

Meaningful title dein. Embedded content ki permissions aur privacy ko bhi carefully consider karein.

25. Kya HTML form validation security ke liye kaafi hai?

Nahi. Client-side checks bypass ho sakte hain. Server par input validate karein aur context ke mutabik safely process/escape karein.

26. HTML “compiler” asal mein kya karta hai?

Typical browser workflow mein HTML compiler nahi, parser/rendering engine document ko parse karke DOM aur visual page banata hai.

27. Kya ek page par multiple h1 allowed hain?

HTML mein multiple h1 technically possible ho sakte hain, lekin clear document hierarchy maintain karein. Ek primary h1 aur logical subsections beginners ke liye achha pattern hai.

28. ARIA kab use karna chahiye?

Pehle native semantic HTML. Jab native markup se required role/state/label express na ho, tab correct ARIA use karein—ARIA native behavior create nahi karta.

29. target="_blank" ke saath kya dhyan rakhein?

User ko batayein ki link nayi tab kholega; external links ke liye rel="noopener noreferrer" ek achha explicit pattern hai.

30. Page language kaise specify karte hain?

Root html element par suitable lang, jaise English ke liye lang="en" aur Hindi ke liye lang="hi".

20. Quick glossary

Markup
Content ke structure/meaning ko tags aur attributes se describe karna.
Element
HTML document ka structured part, jaise paragraph ya link.
Attribute
Element ke baare mein extra information, jaise image ka src.
DOM
Browser ka document object model—parsed document ka tree-like representation.
Semantic
Meaning/role ko clearly express karne wala structure.
Accessibility
Content ko zyada se zyada logon aur input methods ke liye usable banana.
Validation
Markup ko HTML rules ke against check karna; ye complete quality guarantee nahi.
Responsive
Different screen sizes/devices par usable layout.
