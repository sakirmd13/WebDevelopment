2. Internet aur browser knowledge

  • Internet: computers aur devices ko connect karne wala global network.
  • Website: browser mein rendered content aur resources ka collection.
  • Browser: URL se website resources fetch aur HTML/CSS/JS parse/render karta hai. Chrome, Firefox aur Edge common browsers hain.
  • Search engine: search keywords se relevant web pages find karta hai; browser aur search engine alag hain.

1. Web aur HTML basics

HTML kya hai?

HTML ka full form HyperText Markup Language hai. Ye markup language web page ke content ko structure aur meaning deti hai—jaise heading, paragraph, link, image aur form. HTML programming language nahi hai: ismein general-purpose loops ya conditions nahi hote.

HTML ka brief history aur versions

  • 1989-1991: Tim Berners-Lee ne World Wide Web aur HTML ke early ideas develop kiye.
  • HTML 2.0 (1995): HTML ke common features ko standardize karne wala early specification.
  • HTML 3.2 (1997): Tables, applets aur presentation-oriented features ko popular made.
  • HTML 4.01 (1999): Stronger structure aur separation of presentation/structure; strict/transitional frameset variants bhi aaye.
  • XHTML 1.0 (2000): HTML ko XML-like strict syntax mein express kiya; strict parsing aur lowercase tags common the.
  • HTML5 (2014): Semantic elements, audio/video, canvas, form controls aur APIs ka major modern milestone.
  • Modern HTML: WHATWG HTML Living Standard continuous update hota hai; browsers new features ko support status ke according implement karte hain.

HTML

Page ka content aur structure: “ye heading hai”, “ye form hai”.

CSS

Presentation: colors, spacing, layout aur responsive design.

JavaScript

Behavior: button click, validation, calculations aur dynamic updates.

Browser page kaise dikhata hai?

  1. Browser URL se server ko request bhejta hai.
  2. Server HTML bhejta hai; browser usse parse karke DOM tree banata hai.
  3. CSS styles apply hote hain aur JavaScript zarurat par page ko interactive banata hai.
“HTML compiler” ke baare mein: HTML aam taur par compile nahi hota. Browser HTML ko parse karke render karta hai. Isliye is course ka playground editor/preview tool hai—ye code ko browser ke sandboxed preview mein dikhata hai.

Apna pehla HTML file

VS Code ya kisi text editor mein index.html naam ki file banayein. File extension .html honi chahiye. Browser mein file kholkar result dekhein; code badalne ke baad page refresh karein.

2. HTML document ka basic structure

Har normal HTML page mein document declaration, root html, metadata wala head aur visible content wala body hota hai. 

<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Mera pehla page</title>
</head>
<body>
  <h1>Namaste, duniya!</h1>
  <p>Mera pehla HTML page.</p>
</body>
</html>
  • <!doctype html> browser ko modern HTML mode use karne ko kehta hai.
  • <html lang="en"> root element hai. Page Hinglish/Hindi mein ho to lang="hi" ya content ke mutabik sahi language set karein.
  • <head> mein title, metadata aur stylesheets jaise page-related information aati hai.
  • <body> mein page ka visible content hota hai.
  • charset="utf-8" Hindi aur doosre characters ko sahi dikhane mein madad karta hai.
  • Viewport meta mobile browser ko page ki width device ke mutabik set karne deta hai.

HTML comments

Comment browser page par render nahi karta. Iska use code notes ke liye karein; password ya private data comment mein kabhi na rakhein, kyunki source mein dikh sakta hai.

<!-- Ye comment page par nahi dikhega -->
<p>Ye visible paragraph hai.</p>

Head ke common tags

title tab/window ka page title; meta metadata; link external resource; style embedded CSS; base relative URLs ka base URL set karta hai. base ka effect poore document ke relative links par hota hai, isliye ise soch-samajhkar use karein.

<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>HTML Practice</title>
  <link rel="stylesheet" href="style.css">
  <style>
    body { font-family: sans-serif; }
  </style>
</head>

JavaScript file load karne ke liye script use hota hai. External classic script ke liye defer aksar achha default hai; module scripts ka execution behavior alag hota hai. 

<script src="main.js" defer></script>
<script type="module" src="app.js"></script>
  • defer: HTML parse hone ke baad execute; deferred classic scripts document order follow karte hain.
  • async: download ke baad jaldi execute; multiple scripts ka order guaranteed nahi, isliye independent scripts ke liye use karein.
  • type="module": JavaScript module; deferred behavior default hota hai, aur module imports support hote hain.

3. Elements, tags, nesting aur attributes

Tag markup ka start/end syntax hai. Opening tag, content aur closing tag milkar aam taur par ek element banate hain.

<p class="intro">Ye paragraph element hai.</p>
  • <p> opening tag hai; </p> closing tag hai.
  • class="intro" attribute hai—extra information jo element ko identify/style karne mein madad karti hai.
  • Attribute value aam taur par quotes mein likhein.
  • Elements ko sahi order mein nest karein; pehle khula inner element pehle band hota hai.
<p>Ye <strong>important</strong> text hai.</p>
Galat nesting: <p><strong>Text</p></strong>. Ismein tags ka closing order ulta hai.

HTML security basics

HTML user input ko exactly trust nahi kar sakti. XSS (Cross-Site Scripting) tab possible hota hai jab untrusted text ko HTML ke taur par browser mein parse kiya jaata hai. Browser mein dynamic HTML banate waqt textContent/innerText use karein ya server-side/contextual escaping use karein; raw innerHTML se bachein.

<p id="user-output"></p>
<script>
  const untrustedText = "<img src=x onerror=alert('xss')>";
  document.querySelector("#user-output").textContent = untrustedText;
</script>
  • HTML injection: untrusted HTML ko markup ke taur par render mat karein.
  • XSS prevention: output encode karein, trusted templating/DOM APIs use karein, aur server-side allowlists/validation rakhein.
  • Iframes: unknown third-party page ke liye restrictive sandbox aur minimal allow permission use karein.
  • External links: target="_blank" ke saath rel="noopener noreferrer" lagayein; noopener opener tab ko control karne se bachata hai.
  • Forms: browser validation ko security ke replacement ke taur par na lein; HTTPS, CSRF protection, server validation aur secure file handling bhi zaroori hain.
  • CSP: Content Security Policy scripts/styles ke allowed sources aur inline execution ko restrict kar sakti hai; CSP ko defense-in-depth ke taur par configure karein.
  • HTTPS: login, form aur embedded external resources ke liye encrypted transport aur mixed content avoid karna zaroori hai.

19. HTML interview questions aur answers

1. HTML kya hai?

HTML web content ko structure aur meaning dene wali markup language hai. Ye general-purpose programming language nahi hai.

2. HTML ka full form kya hai?

HyperText Markup Language.

3. HTML aur HTML5 mein kya antar hai?

HTML5 HTML standard ka modern generation label tha. Aaj standard WHATWG Living Standard ke roop mein evolve hota hai; semantic, media aur form features modern HTML ka hissa hain.

4. <!doctype html> kyu likhte hain?

Browser ko standards mode mein document parse karne ka signal deta hai; ye normal HTML element nahi hai.

5. head aur body mein kya difference hai?

head mein title/metadata/resources; body mein page ka visible content hota hai.

6. Tag aur element mein kya difference hai?

Tag markup syntax, jaise <p>; element aam taur par opening tag, content aur closing tag ka complete unit hai.

7. Semantic HTML kya hota hai?

Aise elements jo content ka role batate hain, jaise nav, main, article. Ye structure ko readable aur assistive technology ke liye meaningful banate hain.

8. div aur span mein kya difference hai?

Dono generic containers hain. Default display behavior alag hota hai, lekin meaning nahi batate. Suitable semantic element ho to usse prefer karein.

9. Block aur inline elements kya hain?

Ye common default layout behaviors hain: block element aam taur par nayi line se shuru hota hai; inline text flow mein rehta hai. CSS display behavior badal sakta hai.

10. Void element kya hai?

Jis element ka child content/closing tag nahi hota, jaise img, br, hr, input.

11. alt attribute kyu important hai?

Image ka text alternative deta hai—screen reader aur image load na hone par madad karta hai. Decorative image ke liye empty alt="" ho sakta hai.

12. id aur class mein difference?

id ek page par unique identifier hona chahiye; class kai elements share kar sakte hain aur ek element par multiple classes ho sakti hain.

13. Relative aur absolute URL kya hote hain?

Relative URL current/site folder ke hisaab se resolve hota hai; absolute URL mein full scheme aur host hota hai.

14. HTML entities ka use kya hai?

Reserved characters ya special symbols ko text ke roop mein dikhane ke liye, jaise &lt; less-than sign ke liye.

15. Form mein label kaise associate karte hain?

Label ke for attribute ko control ke id ke barabar rakhein; ya control ko label ke andar nest karein.

16. GET aur POST mein difference kya hai?

GET data URL query mein bhej sakta hai aur retrieval/search ke liye suitable hai. POST request body mein data bhejta hai. POST encryption nahi hai; HTTPS zaroori hai.

17. required aur placeholder ka kya kaam hai?

required browser-side constraint validation mein field required banata hai. Placeholder hint hai, label nahi; field ka naam visible label se dena chahiye.

18. Table ko layout ke liye use karna chahiye?

Nahi, table tabular data ke liye hai. Page layout ke liye CSS Flexbox/Grid use karein.

19. strong aur b mein kya difference?

strong importance batata hai; b attention draw karta hai bina extra importance imply kiye. Default visual style CSS se badal sakta hai.

20. em aur i mein difference?

em emphasis deta hai; i alternate voice/mood ya technical term jaisa text mark karta hai. Context ke mutabik chunein.

21. Responsive page ke liye viewport meta kyu hota hai?

Mobile browser ko layout viewport device width se match karne mein madad karta hai, taaki responsive CSS expected tarah kaam kare.

22. defer script attribute ka kya kaam hai?

External script ko HTML parsing ke saath download karke document parse hone ke baad execute karta hai. Ye HTML concept ke saath JS loading ka useful integration point hai.

23. HTML validation kya guarantee karti hai?

Validator markup errors/warnings dhoondhne mein madad karta hai. Pass hona accessibility, security, visual quality ya correct business behavior ki guarantee nahi.

24. iframe ko accessible kaise banayein?

Meaningful title dein. Embedded content ki permissions aur privacy ko bhi carefully consider karein.

25. Kya HTML form validation security ke liye kaafi hai?

Nahi. Client-side checks bypass ho sakte hain. Server par input validate karein aur context ke mutabik safely process/escape karein.

26. HTML “compiler” asal mein kya karta hai?

Typical browser workflow mein HTML compiler nahi, parser/rendering engine document ko parse karke DOM aur visual page banata hai.

27. Kya ek page par multiple h1 allowed hain?

HTML mein multiple h1 technically possible ho sakte hain, lekin clear document hierarchy maintain karein. Ek primary h1 aur logical subsections beginners ke liye achha pattern hai.

28. ARIA kab use karna chahiye?

Pehle native semantic HTML. Jab native markup se required role/state/label express na ho, tab correct ARIA use karein—ARIA native behavior create nahi karta.

29. target="_blank" ke saath kya dhyan rakhein?

User ko batayein ki link nayi tab kholega; external links ke liye rel="noopener noreferrer" ek achha explicit pattern hai.

30. Page language kaise specify karte hain?

Root html element par suitable lang, jaise English ke liye lang="en" aur Hindi ke liye lang="hi".
